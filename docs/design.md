# The exposure instrument

EquityMux starts with **One company. Understand every wrapper.** Its original visual language uses overlapping issuer sleeves, alignment rules, unit conversion and a policy aperture. Every financial outcome comes from the Decimal service.

Deep pine #081C18 is the canvas, graphite #131D1A separates controls, platinum #E5EBE4 carries primary text and the receipt, and citron #D4F36C marks attention. Mint #9CDBB7, coral #FFAD9C and amber #E8CC8B indicate explicit outcomes, always with text. Self-hosted Source Sans 3 handles display and tabular numerals; Source Serif 4 is reserved for small editorial accents. Existing SIL Open Font License files remain.

## The decision journey

The authored SVG sleeve glyphs depict layers and measurement, not issuer logos. Each sleeve exposes token price divided by shares per token resolving to the server's share price. A common zero-based USD/share scale retains differences; unknown observations have no plotted mark. Browser arithmetic only positions marks and formats numbers. It never chooses a financial verdict.

Sleeve, ledger and parity selection stay synchronized. Successful ticker changes clear inspection; failed requests retain previous evidence and inspection. The request source selector and the displayed receipt's own RECORDED/LIVE stamp are separate. Pending requests label the displayed result as previous evidence.

Explain normalization uses a native disclosure and four accessible chapter buttons. It never gates analysis. Short hover transforms provide depth; reduced motion removes transitions. There is no autoplay, synthetic progress or offscreen animation loop. Mobile sleeves become stacked conversions with the shared basis retained. The verdict appears before the policy editor.

The parity graphic uses signed basis-point axes and identifies each observation's reference source and price. Different references do not establish an executable spread. Fees, gas, depth, slippage and reference observation times remain unknown.

The liquidity challenge changes only the applied receipt policy against the same snapshot. Unapplied edits are excluded; restore returns to the actual policy preceding the challenge, including custom same-snapshot premium limits. Unchanged prices sit beside changed checks and outcomes. NO_VALID_ROUTE exposes the service's decisive failed checks.

The platinum receipt exposes snapshot digest, applied policy, normalized alternatives, reasons, hash and NOT_EXECUTED. Verification retries clear old success; pending and partial results remain incomplete. Browser integrity, deterministic replay and provenance-label consistency are distinct claims. None authenticates upstream data or proves a purchase.

## Supporting workspaces

- Explorer: searchable catalog, issuer observations, source labels and explicit unknown market/freshness states. Open status never establishes a fresh price.
- Constitution: supported rules, unsupported sentences, exact JSON disclosure, explicit activation and revision history. Editing invalidates compiled drafts.
- Terminal and routes: recorded transitions, readable reasons, keyboard issuer inspection and the blocked transaction-bound swap simulation capability.
- Receipts: separate execution-pipeline archive, including blocked attempts. Missing provenance reads Unknown and long hashes remain readable.
- Agent: bounded ANALYZE_EXPOSURE tasks, actual integration status and history. The x402 challenge is not represented as payment settlement.
- Diagnostics: fingerprint, execution switch, mode and ceilings first; raw response details behind native disclosures.

All inputs have accessible names. Touch targets, visible focus, native disclosures, Escape-to-close workspace navigation and the skip link remain. Legacy table scrolling belongs to a named keyboard-focusable region. The 360/390/768/1024/1440 layouts widen analytical surfaces instead of shrinking essential labels.
